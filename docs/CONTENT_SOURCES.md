# 多书源与流式内容架构

日期：2026-10-18。目标：同一 ReaderView 支持本地 TXT、EPUB 和网络小说，并允许继续添加格式；分页、滚动、位置恢复和选择共用内容模型。

**当前目标**：所有格式通过同一个 iReadView；EPUB 默认由 EpubReaderBookSource + 自研 EpubReaderBodyView 负责，移除 Readium 运行时，保持 API21，详见[正文层](READER_BODY.md)和[EPUB 接入](EPUB_ENGINE.md)。下面的块模型适用于 TXT、网络小说和显式选择的简化 EPUB 适配；DOM 定位和 UTF-16 锚点分别处理。

## 源码调查与问题

现有 BookSource 已将目录、按章加载与 View 分开，ChapterRepository 已有并发合并、取消、失效和预算，BlockLayoutProvider 已允许自定义块。TXT 已有流式索引，Demo 有 HTTPS JSON 和网站解析两种网络来源。需要扩展现有边界，而不是再创建一套阅读引擎。

缺口集中于 EpubXhtmlParser：img 变成 alt 文本、a 的目标丢失；EpubTextBookSource 的片段解析仅供目录使用。现有默认排版只有文字，没有资源读取和正文链接交互契约。不能把图片标签、链接目标或加载提示塞入可选择的原文。

## 目标和职责

```text
文件/URI/网络输入 → 格式解析或网站适配 → BookSource
                                          ↓
                         BookDescriptor / ChapterContent
                                          ↓
                     文字、带链接文字、图片引用、自定义块
                                          ↓
                 默认/宿主 BlockLayoutProvider → 分页与滚动
```

- BookSource：稳定身份、目录、按章加载；不要求来源必须是文件或 URL。网络加载不下载整本再冒充 TXT。
- ReaderInput：本地文件、ContentResolver、asset 或宿主提供的可重开字节流。扩展格式通过新增 BookSource 解析器接入，无需修改 ReaderView。
- BookResourceSource：可选的按资源 ID 和书籍 revision 读取能力；接收字节预算，返回调用方拥有的字节；不暴露 ZIP、路径或 HTTP 给 View。资源 ID 是来源内的不透明身份。
- BookLinkSource：可选的书内链接到 ReadingPosition 的解析；不存在的章/片段返回 null，不悄悄跳到章首。外部链接只向宿主报告，不自动发起网络或启动 Activity。
- LinkedTextBlock：保持纯 String 原文和 UTF-16 半开链接范围，构造时防御复制并校验；链接元数据变化必须更新 revision。
- ImageBlock：仅保留资源引用、alt 与可选链接，无位图和 View；图片无可选择文字偏移。第一版作为独立块按比例缩放到正文区域，不实现行内图文绕排。
- 默认图片排版：在工作线程按预算读取和解码，几何在发布布局前固定；分页和滚动共用相同片段。失败保留占位与 alt，不让一张坏图阻断整章。自定义 provider 优先。

宿主持有来源生命周期、文件授权、鉴权、HTTP 客户端和磁盘缓存。closeBook 不 close 来源。不同网站/JSON 协议是宿主适配器；库无需网站规则、账号、权限或网络依赖。现有 Demo 网络来源继续使用相同接口。

## EPUB 范围及兼容

保留 EpubTextBookSource 的既有纯文本行为；新增 EpubBookSource 作为流式图片和链接入口。复用现有 ZIP 预算、CRC 校验、私有文件租约、XML 限制、spine 顺序和片段映射。相对路径按 XHTML 所在目录解析；禁止越出容器，书内引用不直接当作本机文件路径。远程图片、脚本、CSS、SVG、音视频、固定版式、完整表格和 DRM 不属于本轮完整支持范围；不支持项给出诊断。

链接区分书内资源/片段和外部 HTTPS/HTTP/mailto；其他协议不成为可执行动作。书内跳转使用现有导航事务并校验内容代次。资源请求携带 revision，来源快照变更应拒绝旧资源，不把新图嵌入旧章节。

第一版默认图片预算：每个资源压缩字节不超过 4 MiB，每图解码工作集不超过 4 MiB，每次章节布局准备的解码总量不超过 16 MiB；同一准备中同资源只读一次。图片按视口采样，超预算或无法解码使用占位；这些是工作集边界，不是进程内存上限，也不构成跨章节资源缓存。宿主可通过优先级更高的自定义 provider 替换。图片不拉伸放大，限制在正文宽高内；图片自身的源位置为 offset=0，模式切换可恢复到该块。

迁移到 Flow 后，书/章 revision 加 `:flow-v1`，避免把旧纯文本锚点或标注默认为同一内容版本；旧标注不自动迁移。文字块内部的选择和标注继续沿用现有实现；跨图片选区、图片书签/标注和无障碍链接动作尚未扩展，不能当作本轮已支持能力。

## 开发顺序与验收

1. 先完成目标、接口、范围和迁移文档（本文）。
2. 增加格式无关图片/链接模型及可选书源能力，保留旧来源兼容。
3. EPUB 保留图片与正文链接，提供资源和片段解析；默认图片排版、链接命中接入两种呈现。
4. Demo 本地 EPUB 改用新入口，保留 TXT 和网络入口；补充宿主接入示例。
5. 构建库和 Demo，记录实际证据。设备验收需覆盖分页/滚动图片、同章/跨章/外链、缺图、超大图、换书取消、旋转/模式切换恢复、选择跨图片。未运行的验收不能标为通过。

增量实施时保持可构建；不顺带修改翻页效果、书架、搜索、标注体系或全局工具配置。既有交接要求未获测试指令时不新增/运行软件测试；本轮先做编译和代码检查，设备交互记录单列。
