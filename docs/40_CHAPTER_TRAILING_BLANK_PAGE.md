# 章节末尾空白页

## 原因与复现

TXT输入的TextLineReader/TextSnapshotParser有意保留空行和原始block身份；Demo使用TRIM_LINE_EDGES只修剪行首尾，不删除空行。StaticLayout为空文本分配一行高度，也会在结尾换行后生成空行。旧PaginationEngine把这些行当作普通排版单元，上一页正文已满时就把尾部空行移到一张新页。

检查内置《妖精之诗》TXT：UTF-8，128章中127章在下一章节标题之前有1个末尾空行。新增回归先在修改前运行，4个用例中3个失败，包含独立空段尾部、单块结尾换行和全空白章。正文中间空行保留用例原本通过。

## 修正范围

PaginationEngine只在可视分页时忽略章节最后有效内容之后的纯空白文本块；最后有效文本块的末尾纯空白行、StaticLayout合成的零长度终行同样不再分页。中间空段照常保留。不改变TXT解析、原文、block ID或contentRevision。

被省略尾部空块的合法源锚点映射到最后一页；最后文本块的结尾偏移继续映射到最后一个可见分片。全空白章节仍保留一张明确空页。没有文本偏移信息的自定义排版单元不按空白行删除，非文本内容块仍视为有效内容。正文片段、选区、引用仍使用未修改的源文本坐标。

连续模式使用同一引擎的可视片段集合，因此也不会保留章节末尾无意义的长空白；内部空白和段距照旧。

## 检查

`ChapterTrailingWhitespaceTest` 4项通过：

1. 最后一页正文填满后，后续空段不产生新页，旧空白锚点仍可恢复。
2. 末尾换行/空白行/合成终行不产生空白页，原文保留。
3. 正文内部空行保留。
4. 全空白章恰好一张空页。

原 `PaginationEngineTest` 3项通过：分片边界与文本不丢失、空章、过高单元拒绝。Debug APK / Release AAR / Maven包构建通过。
