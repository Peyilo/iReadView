# 手势响应与 EPUB 正文交接

本轮目标是缩短触摸到第一帧的等待、保持拖动与动画进度同步，并避免动画结束切回 WebView 时白闪或清晰度跳变。没有缩短动画配置时间；设备对照仍使用240 ms、16 MiB快照预算及同一 ReaderView。

## 开销位置与处理

1. EPUB候选页原先要在手势开始后定位分栏、读回几何并准备截图。现在最多保留三份正文，在阅读空闲时按阅读方向预先定位邻页。命中缓存后不重复JS定位和未变化的页眉页脚绑定。预加载在开始准备导航时取消，不与动画争用WebView/GPU；曾尝试动画期间预加载，实测部分卷页长帧增多，已撤回。取消后检查绑定状态，避免复用尚未初始化完成的文档导致空页或翻页失败。
2. API29+将已排版页面录制为RenderNode显示列表。滑动、覆盖和iBook滑动直接在硬件Canvas重放，不在每帧进入WebView，也不在触摸时临时捕获两份位图。一次动画固定持有自己的录制对象，但其内部仍引用子View的RenderNode，不能当作独立位图；页面显示/停放切换后使缓存失效，重新录制，再用于后续动画。API21–28继续使用预算快照及live兼容路径。
3. page_curl原GLES路径每帧同步glReadPixels，再上传到窗口，容易阻塞UI线程。API33+硬件窗口使用同一材质公式生成RuntimeShader，直接交给窗口GPU绘制；保留48次阴影采样和原效果参数。API21–32及不支持该路径的宿主保留GLES路径。
4. 快照播放期间将正文alpha设为0，替代INVISIBLE，保持WebView的可见生命周期。新增可选SPI `ReadVisualHandoff`：动画遮罩仍在时恢复正文、等待目标WebView的视觉状态与下一帧，然后原子提交位置，最后撤掉遮罩。取消和异常恢复原alpha，不提前提交候选位置。
5. 卷页效果在进度0/1绘制原始页面，避免终点仍显示预算缩小纹理、切回正文后突然变清晰而产生跳动。上述准备不改变拖动距离到进度的映射；手指停住动画也停住，反向拖动即时反向。

## 验证方法

- `ReaderTurnPerformanceTest`：普通文本、同原文EPUB、默认ARM EPUB，全部7种效果，共21组；每组8次前后翻页并采集准备、启动、更新、绘制与Window FrameMetrics，另有42次真实手势提交/取消。无动画耗时不作为动画帧率。
- `ReaderGestureHandoffTest`：三组内容分别验证6种动画，共18组。真实手指事件保持按下、暂停、反向拖动，验证Dragging阶段进度同步，松手前阅读位置不提交。第一帧时间从MOVE送入系统前开始计时。
- 第一帧出现后通过PixelCopy按帧采样正文，到翻页结束后160 ms；彩色背景样本同时检查白屏和纯背景空帧，ARM允许原书本身的白色元素。PixelCopy不是无开销探针，因此不把采样时的帧率作为性能结论，也不能证明所有设备上都没有单像素跳动。
- `PageCurlRuntimeParityTest`在GPU比较新旧材质18组姿态：正负倾斜、三个进度、左右方向，允许有限量化差。不是所有GPU的外观验收。
- 同时运行ARM整章102页前后翻、跨章和最多三份WebView的回归，以及普通文本/EPUB两套选区回归，避免性能改动破坏导航和统一选择。

## 兼容范围

Demo与两库最低版本仍为API21。上述设备测量来自API36模拟器、1080×2424，不能推导为低端真机或API21已验收。首次打开、跨章及预加载未完成时仍有内容准备成本；旧系统的GLES回读成本也仍存在。iBook卷页的持续长帧需结合原始FrameMetrics判断，不以较低的UI draw耗时宣称所有效果达到60fps。

### 当前页消失的修复

用户反馈后通过双色EPUB稳定复现：首次翻页正常，第二次拖动时当前页区域只剩背景，目标页仍显示。修改前 `bothEpubPagesRemainVisibleDuringRepeatedDrags` 在slide第二次拖动失败，当前页指定区域的匹配像素为0。RenderNode录制引用子View显示列表，不能跨页面停放/显示状态无条件复用。现在 `Page.reveal/park` 在alpha状态切换时使录制失效，在新状态重新准备动画表面，保留当前动画已经持有的录制对象。

新增回归使用红蓝交替的独立分页，PixelCopy分别检查当前页与目标页的指定区域；对slide、cover、ibook_slide各连续前翻三次、后翻三次。它能发现过去“整帧不空白”检查漏掉的单页消失问题。修改前日志 `app/build/distinct-pages-before.log`，修复后联合回归日志 `app/build/distinct-pages-regression.log`。

本次联合回归最终 `OK (5 tests)`（93.171秒）：18次双色双页检查、原18组手势/白闪、两套统一选区与ARM102页往返均通过。Debug/AndroidTest APK、EPUB Release AAR构建成功，新Demo APK已安装到API36模拟器。此结论针对当前页消失修复，没有重新测量上轮全部性能数据。
